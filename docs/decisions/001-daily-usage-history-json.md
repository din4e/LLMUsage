# ADR-001：使用 JSON 保存每日用量汇总

## 状态

Accepted

## 日期

2026-07-13

## 背景

仪表盘需要按提供商查询最近 7 日、最近 30 日和全部每日消耗趋势。现有 snapshot cache 只保留每个提供商的最新同步结果，无法形成历史序列。同时，应用仍需保持较小安装体积，当前趋势也不需要保存请求级明细。

## 决策

在应用数据目录中增加独立的 `history/daily-usage.json`，每条记录只包含本地日期、供应商 ID、请求数、Token 数和人民币估算成本。每次成功同步后按“日期 + 供应商”覆盖当天记录。

Tauri 命令 `load_daily_usage` 只返回经过大小、日期、供应商 ID 和数值校验的非敏感汇总。前端负责时间范围与供应商筛选，并使用原生 SVG 渲染 Token 趋势。

## 备选方案

### 立即引入 SQLite

- 优点：适合复杂查询和大量请求级记录。
- 缺点：当前数据量只有每天每供应商一条，增加依赖、迁移和安装体积不划算。
- 结论：保留到请求级历史或本地代理阶段。

### 每次打开页面重新查询历史 API

- 优点：无需本地历史文件。
- 缺点：并非所有供应商都提供日粒度历史接口，也会增加配额消耗和同步延迟。
- 结论：不能作为统一实现。

## 影响

- 趋势从功能上线后的首次成功同步开始积累，不伪造或猜测更早的数据。
- 余额型供应商如果没有 Token 指标，不会被画成零消耗。
- JSON 文件设为 1 MiB 上限；按当前供应商数量可覆盖多年日汇总。
- 将来迁移到 SQLite 时，可直接以“日期 + 供应商”为唯一键导入这些记录。
